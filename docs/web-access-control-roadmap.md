# WEB 접근제어 · Blossom 연동 로드맵

이 문서는 Blossom 접근제어와 WEB 통제를 어떻게 맞출지에 대한 **단계별 로드맵**과 운영 가이드입니다.  
관리자는 **설정 > 접근제어**에서 일부 옵션을 저장할 수 있으며, 세부 내용은 아래와 같습니다.

## Phase 1 — 역할 분리 및 문서화 (기본)

| 구분 | 내용 |
|------|------|
| Blossom | 권한·승인·만료·접속(시도) 감사, WEB/SSH 접속 UX |
| 역프록시 / ZTNA / SWG | 실제 트래픽 허용·URL 통제·상세 접근 로그 |
| IdP | 인증·역할 |

- 사용자에게 허용할 URL은 가능하면 **짧은 진입점**(SSO 랜딩, 사내 포털, 게이트 경로)으로 자원에 등록하는 것을 권장합니다.
- 상세 URL/클릭 체인까지의 감사는 **게이트웨이 로그**와 병행하는 것이 일반적입니다.

## Phase 2 — 호스트 게이트(설정 반영)

**설정 > 접근제어 > WEB 접속 통제**의 **「허용 호스트 패턴」**에 한 줄에 하나씩 문자열을 넣습니다.

- 목록이 **비어 있으면** 게이트 검사 없음(기존과 동일).
- **비어 있지 않으면**, 사용자가 WEB 접속 시 **접속 URL의 호스트명**이 패턴 중 하나와 일치(완전 일치 또는 **부분 문자열 포함**)해야만 접속이 진행됩니다.
- 인프라에서 허용한 게이트 도메인만 등록하는 용도입니다(오타·무단 URL 완화).

## Phase 3 — iframe 패널 모드(선택)

**「WEB 열기 방식」**을 **새 탭** 또는 **iframe(이 페이지 안)** 으로 선택할 수 있습니다.

- iframe은 **주소창이 Blossom URL을 유지**하는 효과가 있으나, 대상 사이트가 `X-Frame-Options` / CSP `frame-ancestors` 로 막으면 **표시되지 않습니다**.
- **「iframe 허용 호스트 패턴」**이 비어 있으면 iframe 모드여도 **새 탭으로 대체**됩니다.
- 패턴이 있고 호스트가 일치할 때만 iframe 모드를 적용합니다.

## Phase 4 — 감사 기대치

| 항목 | Blossom | 게이트/프록시 |
|------|---------|---------------|
| 승인·권한·만료 | 예 | - |
| 접속 버튼 클릭(의도) | 예 | 선택 |
| 세션 종료(탭 닫힘 등 근사) | WEB/SSH 일부 | - |
| 모든 하위 URL·클릭 | 제한적 | 권장 |

## 관련 코드·API

- 관리자 정책: `GET/PUT /api/access-control/policy` (관리자)
- 사용자 브라우저 정책: `GET /api/access-control/browse-policy` (로그인 사용자)
- DB: `web_access_policy` 컬럼 `web_open_mode`, `web_iframe_allow_patterns`, `web_host_gate_patterns`, `web_infra_runbook`

## 인프라 담당자용 메모

**설정 > 접근제어**의 **「인프라/게이트웨이 운영 메모」**는 DB에 저장되며, 관리자가 역프록시 URL, 담당 팀, 변경 이력 등을 적어 두는 용도입니다. Blossom은 이 텍스트를 **표시만** 하고 자동 연동하지 않습니다.
